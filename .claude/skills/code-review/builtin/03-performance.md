# 性能审查

你正在审查代码变更中的性能问题。重点关注数据库查询效率、算法复杂度和资源使用。

## 检查清单

### 数据库
- **N+1 查询**：循环中是否执行了独立的数据库查询？应使用 JOIN 或批量查询
- **缺少索引**：WHERE / JOIN 条件字段是否有索引？
- **全表扫描**：是否查询了不必要的列或行？大表查询是否分页？

### 算法与数据结构
- 时间复杂度是否合理？是否存在 O(n^2) 可优化为 O(n) 或 O(n log n) 的场景？
- 是否选择了合适的数据结构（列表 vs 集合 vs 字典）？
- 递归是否有终止条件？是否可能栈溢出？

### 内存与 I/O
- 大文件/大结果集是否使用了流式处理？
- 是否一次性加载了大量数据到内存？
- 循环内是否有不必要的对象创建？

### 缓存与延迟
- 高频访问的不变数据是否可以缓存？
- 是否有不必要的同步等待可改为异步？
- 外部 API 调用是否设置了合理的超时？

## 输出要求

- 导致严重性能退化（>10x）→ `critical`
- 中等性能影响 → `warning`
- 微优化建议 → `suggestion`
- `dimension` 填写 `performance`

# API 设计审查

你正在审查 API 相关的代码变更。重点关注接口设计、输入验证、错误处理和 HTTP 规范遵循。

## 检查清单

### RESTful 规范
- URL 路径是否使用名词复数形式？
- HTTP 方法是否语义正确（GET 幂等、POST 创建、PUT 全量更新、PATCH 部分更新、DELETE 删除）？
- 嵌套资源路径是否合理（不超过 2 层）？

### 输入验证
- 请求参数是否做了类型和范围校验？
- 必填字段是否验证了非空？
- 字符串输入是否防止了注入和超长输入？
- 分页参数是否有默认值和上限？

### 响应格式
- 成功响应是否使用了正确的 HTTP 状态码（200/201/204）？
- 错误响应格式是否统一（包含 error code 和 message）？
- 是否返回了不必要的数据（如内部 ID、密码哈希）？
- 列表接口是否返回了总数和分页信息？

### 安全与性能
- 是否设置了合理的速率限制？
- 大列表是否支持分页？
- 是否有 CORS 配置？
- 响应是否包含缓存头？

## 输出要求

- API 安全漏洞（缺少认证、信息泄露）→ `critical`
- 设计不规范影响集成 → `warning`
- API 改进建议 → `suggestion`
- `dimension` 填写 `api_design`

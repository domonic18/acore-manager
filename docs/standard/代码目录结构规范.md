# 代码目录结构规范

> 版本：v1.0（2026-09-22）
> 适用范围：`backend/` 与 `frontend/` 全部源码
> 参考项目：[ai-invest-assisstant](../../../../ai-invest-assisstant/) 的分层纪律（层内按域分组、agent 模块族 core/runtime/tools/skills 分离、业务编排与运行时机制分层）
> 关联文档：[数据库操作规范.md](./数据库操作规范.md)、[arch/06AI诊断与Agent架构.md](../arch/06AI诊断与Agent架构.md)

## 一、总则

1. **目录即架构**：本仓库按「分层 + 域分组」组织代码，每个文件必须有且只有一个归属目录；新建目录前先查本文档，本文档没有的目录不允许出现。
2. **变更须登记**：新增顶层目录 / 新增域分组子目录（如 `services/xxx/`、`features/xxx/`），必须先修订本文档再落代码。
3. **拒绝散落**：不允许在目录根堆放与该层职责不符的文件；临时实验代码一律进 `backend/poc/`（不参与构建），验证后转正到规范位置或删除，**poc 代码不得被生产代码 import**。
4. **两条命名主线**：
   - 后端：层文件 `xxx.{routes,service,entity}.ts`；域分组目录直接用域名（`services/ai/`）
   - 前端：域目录用 kebab-case（`features/ai-assistant/`）；组件文件 PascalCase；其余 camelCase

## 二、后端结构（backend/src/）

```

│   ├── config/                     # 环境与数据源配置（env.ts / database.ts / load-env.ts）

│   ├── agent/                      # AI Agent 运行时机制（与业务编排分离，见 2.1）
│   │   ├── core/                   #   提示词加载、skills 目录加载器
│   │   ├── runtime/                #   model-factory / agent-factory / checkpointer / budget-guard / wire(SSE 事件映射)

│   ├── shared/                     # 跨层通用：utils/（aes 等）、enums/、errors/（ServiceError 唯一定义点，各服务 re-export）
```

### 2.1 `agent/` 与 `services/ai/` 的边界（关键规则）

参考 ai-invest 的 `app/agent/`（运行时机制）与 `app/services/assistant/`（业务编排）分离：

| 判定问题 | 归属 |
|---------|------|
| 换一个 LLM 供应商/协议/提示词，这段代码要跟着变吗？ | **要 → `agent/`**（模型客户端分派、agent 组装、checkpointer、工具实现、SSE 事件映射） |
| 这段代码描述的是"ACM 的一个业务流程"吗？ | **是 → `services/ai/`**（巡检怎么编排、报告怎么落库、预算怎么告警、会话怎么管理） |
| 它是 HTTP 入口吗？ | `routes/ai-*.routes.ts`（薄，不含业务） |
| 它是表结构吗？ | `entities/acm/` |

- 依赖方向（单向，禁止反向）：`routes/` → `services/ai/` → `agent/` → `entities/` / `shared/`
- `agent/` 内部**不 import** `services/`；`services/ai/` 之间可互相调用，但不得绕过 `agent/` 直接操作 LangGraph 对象

### 2.2 后端禁令

- 禁止在 `routes/` 写业务逻辑（SQL 编排、加解密、第三方调用）
- 禁止游戏三库（auth/characters/world）出现写操作；可写仅限 `acm` 数据源，且只经 `services/ai/`
- 禁止新增 `entities/` 下与数据源名不符的目录；禁止 `synchronize: true`
- 禁止在 `src/` 任意位置新建 `utils/`、`common/`、`helper/` 之类杂项目录——通用代码进 `shared/`
- 禁止 poc/ 代码被 src/ import；poc 验证完成后必须转正或删除
- **导入路径约定**：跨目录导入一律用 `@/` 别名（tsconfig paths + build 时 tsc-alias 改写，jest 经 moduleNameMapper）；同目录保持 `./` 相对导入；禁止 `../` 上溯式相对路径

## 三、前端结构（frontend/src/）

维持 feature-based（15 个存量 feature 已成型，不向 ai-invest 的按层平铺重构），纪律参考 ai-invest 的组件内分层（assistant/ 下 composer/messages/ui 分层）：

```
frontend/src/
├── app/                        # router、全局 provider、守卫装配
├── features/                   # 按域组织，目录名 = 业务域（kebab-case）
│   └── {domain}/               # 每个域固定子集，允许的子目录仅以下四种：
│       ├── api/                #   接口定义与调用（xxx.api.ts）
│       ├── hooks/              #   TanStack Query hooks（useXxx.ts）
│       ├── types/              #   该域类型（可并入 api，复杂时独立）
│       └── components/         #   该域专用组件（跨域复用禁止放这里）
├── pages/                      # 仅页面壳：路由入口组件（XxxPage.tsx，≤ ~100 行），逻辑下沉 feature
├── shared/                     # 跨 feature 通用（判定标准：≥2 个 feature 需要才可进）
│   ├── api/                    #   apiClient、拦截器
│   ├── components/             #   AppLayout / Dialog / SimpleTable（通用表格）/ PaginationBar / StatusBadge /
│   │                           #   InfoCard / ConfirmDialog / BanFlowDialogs（封禁双 Dialog 流程）/ BanHistoryTable /
│   │                           #   TimeRangeFilter / CopyButton / Markdown；ui/ 为基础组件（shadcn）
│   ├── hooks/                  #   useAuth / usePermission / useRowSelection（表格多选）/ useBanFlow（封禁流程状态机）/ useDefaultRealm（系统配置只读）
│   ├── utils/                  #   gold.util（金币换算）/ toast.util 等
│   ├── api/                    #   ↑含 system-config.api（只读视图，多 feature 消费）
│   └── constants/  config/  lib/  #  lib/ 含 ai-quick-analyze（详情页→AI 助手桥接，3 feature 共用）
├── styles/                     # 全局样式
└── __tests__/                  # 测试（镜像 src 结构）
```

### 3.2 前端禁令

- 禁止绕过 `features/{domain}/api/` 直接在组件里 fetch；必须走 `shared/api/` 的 apiClient
- 禁止在 `pages/` 写业务逻辑（页面壳超过 ~100 行即应下沉 feature）
- 禁止组件跨 feature import（`features/a/` 不得 import `features/b/`）；需要复用则上提 `shared/`
- 禁止在 `shared/` 出现仅单一 feature 使用的代码；反向不成立（feature 专用代码不得进 shared）
- 路由注册只在 `app/router.tsx`；菜单只在 `shared/components/AppLayout.tsx`

## 四、与 ai-invest-assisstant 的组织哲学对照

| ai-invest（Python） | acore-manager（TS）对应 | 说明 |
|---------------------|------------------------|------|
| `app/api/v1/` | `routes/` | 薄路由；ACM 域规模小，用前缀而非子目录 |
| `app/services/{域}/` | `services/{域}/`（现状仅 `ai/`） | 域分组；存量扁平域暂不迁移 |
| `app/repositories/{域}/` | `repositories/` | ACM 游戏库只读查询 |
| `app/models/` + `app/schemas/` | `entities/{库}/` + 各域 `types` | TypeORM 实体按数据源分组 |
| `app/agent/{core,runtime,tools,skills}` | `agent/{core,runtime,tools,skills}` | **同名同职责**，运行时机制与业务分离 |
| `app/prompts/` | `agent/prompts/` | 提示词 YAML 随 agent 模块族 |
| `web/src/api/` + `web/src/components/{域}/` | `features/{域}/{api,components}` | ACM 用 feature-based 收敛域内聚 |
| `web/src/pages/` | `pages/` | 均为页面壳 |
| `web/src/components/assistant/composer|messages|ui` | `features/ai-assistant/components/*` | 组件内部分层纪律一致 |

## 五、新增代码落位速查

| 要写的东西 | 放哪 |
|-----------|------|
| 新 HTTP 端点 | `routes/xxx.routes.ts`（薄）+ `services[/ai]/xxx.service.ts`（逻辑） |
| 新 AI 白名单工具 | `agent/tools/{db-tools,log-tools}/` + 在 `agent/tools/registry.ts` 注册 |
| 新系统提示词 | `agent/prompts/{scene}.yaml` |
| 新 acm 表 | `entities/acm/xxx.entity.ts` + `docker/database/migrations/YYYYMMDD_NN_xxx.sql` |
| 新页面 | `pages/XxxPage.tsx`（壳）+ `features/{domain}/`（逻辑）+ `app/router.tsx` 注册 |
| 新 SSE 事件类型 | `agent/runtime/wire.ts` 定义 + `docs/arch/06` 5.2 协议表同步 |
| 实验性验证代码 | `backend/poc/{topic}/`，README 说明验证目标与结论 |
| 一次性运维脚本 | `backend/src/scripts/`（可 import src），或 `ops/`（游戏服侧 shell） |

# acore-manager 部署架构设计

## 一、部署模式

### 1.1 单体容器部署

前后端构建为**单一 Docker 镜像**，由 Express 统一托管：

| 层级 | 处理方式 | 说明 |
|------|---------|------|
| **前端** | Vite 构建产物 → 静态文件 | 由 Express `express.static()` 托管 |
| **后端** | Express API → `/api/*` 路由 | 业务逻辑、数据库查询、缓存、SOAP 调用 |
| **SPA Fallback** | `/*` → `index.html` | 支持 React Router BrowserHistory |

**优势**：
- 腾讯云 SCF 只需部署**一个云函数**，一个容器实例
- 减少网络延迟（前端→后端为同容器内部调用）
- 简化运维（单镜像、单容器、单日志流）
- 避免前后端分离部署的 CORS 和跨域配置复杂度
- 管理后台无需考虑 iframe 嵌入场景，CORS 配置更简单

## 三、统一 Dockerfile

```dockerfile
# docker/Dockerfile
# 前后端统一构建，输出单一可运行镜像

# Stage 1: Frontend build
# Use Debian-based image because rolldown (Vite 8 bundler) lacks musl native bindings
# node:22：deepagents 传递依赖 openai@7 要求 node>=22，且 npm 10.8(node20) 有 Exit handler never called 损坏安装 bug
FROM node:22 AS frontend-builder
WORKDIR /app/frontend

ARG VITE_APP_VERSION
ENV VITE_APP_VERSION=${VITE_APP_VERSION}

COPY frontend/package*.json ./
RUN npm ci --legacy-peer-deps
COPY frontend/ ./
RUN npm run build

# Stage 2: Backend build
FROM node:22-alpine AS backend-builder
WORKDIR /app/backend
COPY backend/package*.json ./
RUN npm ci --legacy-peer-deps
COPY backend/ ./
RUN npm run build

# Stage 3: Production
FROM node:22-alpine AS production
WORKDIR /app
# Install fonts required by svg-captcha on Alpine Linux (Alpine 3.18+: ttf-dejavu → font-dejavu)
RUN apk add --no-cache fontconfig font-dejavu
COPY backend/package*.json ./
RUN npm ci --legacy-peer-deps --omit=dev && npm cache clean --force
COPY --from=backend-builder /app/backend/dist ./dist
COPY --from=frontend-builder /app/frontend/dist ./dist/public
RUN addgroup -g 1001 -S nodejs && adduser -S nodejs -u 1001
USER nodejs
EXPOSE 9000
CMD ["node", "dist/server.js"]
```

巡检 Job 镜像（`docker/Dockerfile.job`）复用同一后端构建产物，仅含生产依赖与 `dist/`，固定入口 `dist/job/job-entry.js`，通过环境变量 `SCF_CUSTOM_CONTAINER_EVENT`（JSON 契约 `{"task":"inspection","params":{...}}`）路由任务，跑完进程退出：

```dockerfile
# docker/Dockerfile.job（节选 Stage 2）
FROM node:22-alpine AS job-runtime
WORKDIR /app
COPY backend/package*.json ./
RUN npm ci --legacy-peer-deps --omit=dev && npm cache clean --force
COPY --from=backend-builder /app/backend/dist ./dist
USER nodejs
ENTRYPOINT ["node", "dist/job/job-entry.js"]
```

### 镜像体积优化

| 阶段 | 体积 | 说明 |
|------|------|------|
| 前端构建 | ~350MB（含 node_modules）| 中间层，不进入最终镜像 |
| 后端构建 | ~450MB（含 node_modules）| 中间层，不进入最终镜像 |
| **生产镜像** | **~130MB** | 仅含运行时 + 编译产物 + 生产依赖 |

## 四、Express 静态文件托管与路由配置

生产环境下，Express 同时承担 API 服务和静态文件托管职责：

```typescript
// backend/src/app.ts

import express, { Application } from 'express';
import path from 'path';

export function createApp(): Application {
  const app = express();

  // 1. 安全中间件
  app.use(helmet());
  app.use(cors({ origin: process.env.ALLOWED_ORIGINS?.split(',') || [] }));

  // 2. 解析中间件
  app.use(express.json());
  app.use(express.urlencoded({ extended: true }));

  // 3. 日志与格式化
  app.use(requestLogger);
  app.use(responseFormatter);

  // 4. API 路由（必须在静态文件之前注册，避免被 SPA fallback 拦截）
  //    /api/* 先过数据库就绪门控，DB 未就绪时返回 503 + Retry-After
  app.use('/api', dbReadinessGate);
  app.use('/api/auth', authRoutes);
  app.use('/api/accounts', accountRoutes);
  app.use('/api/characters', characterRoutes);
  app.use('/api/transactions', transactionRoutes);
  app.use('/api/gm', gmToolRoutes);
  app.use('/api/ip-bans', ipBanRoutes);
  app.use('/api/banlist', banlistRoutes);
  app.use('/api/mutes', muteRoutes);
  app.use('/api/audit', auditLogRoutes);
  app.use('/api/dashboard', dashboardRoutes);
  app.use('/api/rbac', rbacRoutes);
  app.use('/api/system-config', systemConfigRoutes);
  app.use('/api/ai/model-configs', aiModelConfigRoutes);
  app.use('/api/ai/token-usage', aiTokenUsageRoutes);
  app.use('/api/ai/diagnosis', aiDiagnosisRoutes);
  app.use('/api/ai/assistant', aiAssistantRoutes);
  app.use('/api/ai/analysis', aiAnalysisRoutes);
  app.use('/api/health', healthRoutes);   // 健康检查豁免就绪门控

  // 5. 静态文件托管（前端构建产物）
  app.use(express.static(path.join(__dirname, 'public')));

  // 6. SPA fallback：所有非 API 请求返回 index.html
  // 支持 React Router 的 BrowserHistory 模式
  app.get('*', (_req, res) => {
    res.sendFile(path.join(__dirname, 'public', 'index.html'));
  });

  // 7. 全局错误处理（末尾注册）
  app.use(errorHandler);

  return app;
}
```

### 路由优先级说明

```
请求到达顺序：
  /api/auth/login       → 就绪门控 → API 路由处理（第 4 步）
  /api/accounts         → 就绪门控 → API 路由处理（第 4 步）
  /api/health           → API 路由处理（豁免就绪门控）
  /assets/icons/xxx.png → 静态文件（第 5 步）
  /dashboard            → SPA fallback → index.html（第 6 步）
  /characters/123       → SPA fallback → index.html（第 6 步）
```

> **注意**：API 路由必须注册在 `express.static()` 之前，否则 `/api/health` 等路径可能被误判为静态文件请求。

## 五、本地开发（Docker Compose）

```yaml
# docker-compose.yml
services:
  # acm 系统自有库（可写）：模型配置 / 会话 / LangGraph checkpoint（PostgresSaver 无模块依赖）
  # 游戏三库仍在 acore-mysql（只读），两者隔离
  acm-postgres:
    image: postgres:16-alpine
    ports:
      - "5433:5432"
    environment:
      - POSTGRES_USER=acm
      - POSTGRES_PASSWORD=${ACM_PG_PASSWORD}
      - POSTGRES_DB=acm
    volumes:
      - acm_pgdata:/var/lib/postgresql/data
    restart: unless-stopped

  app:
    build:
      context: .
      dockerfile: docker/Dockerfile
      target: production
      args:
        VITE_ICON_BASE_URL: ${VITE_ICON_BASE_URL}
        VITE_AOWOW_BASE_URL: ${VITE_AOWOW_BASE_URL}
    ports:
      - "9010:9000"
    env_file:
      - .env
    environment:
      - NODE_ENV=production
    depends_on:
      - acm-postgres
    restart: unless-stopped

volumes:
  acm_pgdata:
```

游戏三库（acore_auth / acore_characters / acore_world）MySQL 与 Redis 通常来自外部 AzerothCore 部署，不在本地 compose 内启动；e2e 验证使用 `docker-compose.e2e.yml` 额外补齐 MySQL / Redis / scf-mock。

### 本地快速启动

```bash
# 1. 复制环境变量模板
cp .env.example .env
# 编辑 .env 填入实际的数据库、Redis、JWT、SOAP 连接信息

# 2. 构建并启动
make build && make up
# 或
docker-compose up --build -d

# 3. 查看日志
docker-compose logs -f app

# 4. 访问
open http://localhost:9000
```

### 6.1 部署流程

```
代码提交 → GitHub Actions 触发
    │
    ▼
┌──────────────────────────────┐
│ Stage 1 前端 lint/test/build  │
│ Stage 2 后端 lint/tsc/test    │   （并行，PR 只跑这两段）

    │  push develop/main 继续
    ▼
┌──────────────────────────────┐
│ Stage 3 双镜像并行构建推送     │
│  docker-app → acore-manager   │
│  docker-job → acore-manager-job│
│ （步骤级超时 + 失败重试一次）  │
└──────────────────────────────┘
    │
    ▼
腾讯云 SCF：Web 函数更新镜像 / Job 函数按需更新
```

流水线细节（触发条件、缓存、跨境推送稳定性）见 [05CI设计.md](./05CI设计.md)。

### 6.2 TCR 镜像仓库配置

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 仓库地址 | `ccr.ccs.tencentyun.com` | 腾讯云容器镜像服务 |
| 命名空间 | `${TCR_NAMESPACE}` | 来自 GitHub Secrets |
| 镜像名称 | `acore-manager` / `acore-manager-job` | Web 单体镜像 + 巡检 Job 镜像 |
| 镜像标签 | `{分支}-{short_sha}` + `latest` | 回滚用 sha 标签，生产跟踪 latest |
| 构建参数 | `provenance: false` | TCR 不认 buildx attestation manifest |
| 缓存 | `type=gha` | 加速重建与失败重推 |

### 6.3 SCF 函数配置

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 函数类型 | Web 函数 | 支持 HTTP 触发 |
| 运行环境 | 自定义容器 | 使用 TCR 镜像 |
| 监听端口 | 9000 | 与 Dockerfile EXPOSE 一致 |
| 内存 | 512MB | 管理后台并发量低，512MB 足够 |
| 超时时间 | 30s | 数据库查询 + SOAP 调用预留 |
| 并发配额 | 按需求调整 | 内部 GM 工具，并发通常很低 |

## 九、前端构建产物路径说明

### Vite 配置调整

前端构建输出目录使用默认 `frontend/dist`，在 Dockerfile Stage 3 中被复制到后端产物目录：

```typescript
// frontend/vite.config.ts

export default defineConfig({
  // ... 其他配置
  build: {
    outDir: 'dist',           // 默认输出目录
    emptyOutDir: true,        // 构建前清空
    // 前端产物最终被复制到 backend/dist/public/
  },
});
```

### 生产环境 API 调用

由于前后端同域部署，前端 API 调用无需指定完整域名：

```typescript
// src/shared/api/client.ts

const API_BASE_URL = import.meta.env.VITE_API_BASE_URL || '';
// 生产环境: VITE_API_BASE_URL = ''（空字符串）
// 请求 /api/auth/login 会被同域 Express 处理
```

开发环境可通过 `.env.development` 配置代理：

```bash
# frontend/.env.development
VITE_API_BASE_URL=http://localhost:9000
```

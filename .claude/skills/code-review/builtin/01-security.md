# 安全审查

你正在审查代码变更中的安全问题。请逐一检查以下类别，发现任何违规即报告为 finding。

## 检查清单

### 注入攻击
- **SQL 注入**：是否使用参数化查询 / ORM？是否存在字符串拼接 SQL？
- **XSS（跨站脚本）**：前端是否对用户输入做了转义？后端是否返回未编码的 HTML？
- **命令注入**：是否将用户输入传递给 `os.system`、`subprocess` 等调用？
- **路径遍历**：文件操作是否校验了 `../` 等路径穿越符号？

### 凭证与密钥
- 硬编码的 API key、token、密码、数据库连接串
- `.env` 或配置文件中的敏感信息是否可能被提交到版本库
- 日志中是否意外打印了认证 token、密码等敏感数据

### 数据安全
- 不安全的反序列化（如 `pickle.loads` 用户输入）
- 敏感数据未加密传输或存储
- 错误信息中暴露了内部实现细节（堆栈、SQL、文件路径）

### 认证与授权
- API 端点是否缺少认证校验
- 权限提升风险（普通用户可访问管理员接口）
- CSRF token 是否缺失

## 输出要求

- 安全问题 severity 必须为 `critical`（除非影响极低）
- `dimension` 填写 `security`
- `suggestion` 必须包含具体的修复方案

# acore-manager 整体架构设计

## 一、系统概述

acore-manager 是一个面向 AzerothCore 魔兽世界私服的**全端管理后台系统**，支持桌面端和移动端浏览器访问。通过 Web 界面提供对游戏数据库和玩家数据的全面管理能力，让服务器管理员和 GM **随时随地**（包括通过手机、平板）完成日常管理工作。

### 1.1 设计目标

| 目标 | 说明 |
|-----|------|
| 全端适配 | 响应式布局，同时支持 PC 桌面端和移动端浏览器访问 |
| 权限分级 | 基于 AzerothCore GM 等级（gmlevel 1-4）的细粒度权限控制 |
| 操作安全 | 敏感操作二次确认、全量操作日志审计、SHA1 密码标准 |
| 技术一致性 | 后端技术栈与 `acore-ranking` 保持一致，降低维护成本 |
| 云原生部署 | 单一 Docker 镜像，支持腾讯云 SCF Web 容器快速部署 |
| 原生兼容 | 只读取/修改 AzerothCore 已有表结构，不引入额外模块依赖 |

### 1.2 与 acore-ranking 的关系

| 项目 | 定位 | 用户群体 | 核心能力 |
|------|------|---------|---------|
| **acore-ranking** | 数据展示服务（只读） | 普通玩家 | 排行、统计、iframe 嵌入 |
| **acore-manager** | 管理后台系统（读写） | GM / 管理员 | 账号/角色管理、GM 工具、日志审计 |

两者共享同一套后端技术栈（Express + TypeORM + Redis），但部署为**独立服务**（不同端口），互不冲突。

### 2.2 选型理由

**为什么选 Express（而非 NestJS）？**

acore-manager 最初使用 NestJS 搭建，但考虑到以下因素，统一采用 Express：
- 与 `acore-ranking` 技术栈保持一致，后端代码风格、目录结构、中间件机制完全复用
- Express 轻量灵活，对于管理后台的 API 规模（< 30 个端点）完全足够
- 分层架构（routes / services / repositories / entities）由代码组织实现，无框架约束
- 云函数冷启动更快

**为什么选 React + Vite（而非 Vue）？**

- 与 `acore-ranking` 前端技术栈统一
- shadcn/ui 生态更丰富，后台管理类组件（表格、表单、对话框）开箱即用
- TanStack Table 在复杂数据表格场景下比 Element Plus 更灵活

## 三、系统架构图

### 3.1 全局架构（单体容器部署）

前后端构建为**单一 Docker 镜像**，Express 同时托管 API 服务和前端静态文件：

```
  ┌─────────────────────────────────────────────────────────────────────┐
  │  浏览器用户（PC / 平板 / 手机）                                       │
  │  - 管理员后台操作                                                    │
  │  - GM 移动端应急处理                                                  │
  └─────────────────────────┬───────────────────────────────────────────┘
                            │ HTTPS
                            ▼
  ┌─────────────────────────────────────────────────────────────────────┐
  │  腾讯云 SCF Web 容器 / Docker 容器（单一镜像）                          │
  │                                                                      │
  │  ┌──────────────────────────────────────────────────────────────┐   │
  │  │  Express Server :9000（SCF 默认端口）                         │   │
  │  │                                                              │   │
  │  │  /api/*    → API 路由（JWT 鉴权 + GM 等级权限校验）            │   │
  │  │  /assets/* → 静态资源（前端构建产物）                           │   │
  │  │  /*        → SPA fallback → index.html                        │   │
  │  │                                                              │   │
  │  │  ├─ Routes        → HTTP 路由层（薄路由，参数校验）              │   │
  │  │  ├─ Services      → 业务逻辑层（账号/角色/GM 工具/日志）         │   │
  │  │  ├─ Repositories  → 数据访问层（TypeORM 多数据源查询）           │   │
  │  │  ├─ Entities      → 数据库实体（auth/characters/world + acm）    │   │
  │  │  ├─ Middleware    → JWT 鉴权 / GM 权限 / 请求日志 / 响应格式化    │   │
  │  │  └─ Shared        → 工具函数 / 常量 / 类型定义                  │   │
  │  └──────────────────────────────────────────────────────────────┘   │
  │                                                                      │
  └────────────────────────────┼─────────────────────────────────────────┘
                               │
       ┌────────┬────────┼─────────┬──────────┐
       ▼        ▼        ▼         ▼          ▼
  ┌───────┐ ┌───────┐ ┌──────────┐ ┌────────┐ ┌─────────┐
  │ Redis │ │ MySQL │ │PostgreSQL│ │ SOAP/RA│ │ LLM API │
  │ (缓存) │ │(AzerothCore)│(acm 自有库)│ │(GM 命令)│ │(模型出口)│
  └───────┘ └───┬───┘ └──────────┘ └────────┘ └─────────┘
                │
     ┌──────────┼───────────┐
     ▼          ▼           ▼
  acore_auth  acore_characters  acore_world
  (账号/权限)   (角色/数据)      (模板数据)
```

### 3.2 数据流

```
用户请求（PC / 移动端）
    │
    ▼
┌─────────────────────────────────────┐
│  前端路由匹配对应页面                  │
│  页面组件加载时发起 API 请求           │
│  JWT Token 自动附加到请求头            │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│  Express Middleware 层               │
│  - JWT 鉴权（验证 Token 有效性）       │
│  - GM 等级守卫（校验功能访问权限）      │
│  - 请求日志记录（pino 结构化日志）      │
│  - 异常统一处理                        │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│  Service 层                         │
│  1. 尝试从 Redis 读取缓存数据          │
│  2. 缓存命中 → 直接返回                │
│  3. 缓存未命中 → 查询 MySQL（只读）/ PostgreSQL（acm）   │
│  4. 写入 Redis 缓存并返回              │
│  5. GM 命令 → 调用 SOAP/RA 接口        │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│  Repository 层 (TypeORM)            │
│  执行 SQL 查询（多数据库连接）          │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│  响应数据格式化 → JSON 响应 → 前端渲染  │
└─────────────────────────────────────┘
```

## 五、权限架构

### 5.1 GM 等级与功能映射

| GM 等级 | 角色 | 可访问功能 |
|:-------:|------|-----------|
| 4 | 超级管理员 (Owner) | 全部功能（账号管理、角色管理、GM 工具、日志审计、系统设置） |
| 3 | 管理员 (Admin) | 账号管理、角色管理、GM 工具、日志审计 |
| 2 | 游戏管理员 (GM) | 角色管理（查看）、GM 工具（广播、查找玩家）、日志查看 |
| 1 | 初级 GM (Moderator) | 角色列表查看、交易记录查询、在线玩家查看 |

### 5.2 权限校验流程

```
用户请求 API
    │
    ▼
JWT 鉴权中间件
    - 验证 Token 有效性
    - 解析用户 ID 和 gmlevel
    │
    ▼
GM 等级守卫中间件
    - 根据路由配置读取所需 gmlevel
    - 对比用户 gmlevel >= 所需等级
    - 不足 → 返回 403 Forbidden
    │
    ▼
业务逻辑处理
```

### 5.3 前端权限控制

- **路由级**：React Router 守卫，无权限时重定向到 Dashboard
- **菜单级**：Sidebar 根据 `user.gmlevel` 动态渲染菜单项
- **按钮级**：敏感操作（封禁、修改配置）按钮通过 `usePermission` Hook 控制显隐
- **二次确认**：危险操作弹出确认对话框，要求输入确认文字

## 六、环境变量配置

```bash
# .env.example（完整模板以仓库根目录 .env.example 为准，连接串风格）

# ==========================================
# 应用配置 / Application Config
# ==========================================
NODE_ENV=production
PORT=9000
LOG_LEVEL=info
# 监听前等待数据库初始化的预算（毫秒）；耗尽则转 degraded 继续监听，后台无限重试自愈
STARTUP_DB_BUDGET_MS=15000

# ==========================================
# 数据库配置（AzerothCore，只读连接）
# 支持连接串或分字段配置，连接串优先
# ==========================================
DB_URL=mysql://user:pass@host:port
DB_AUTH=acore_auth
DB_CHARACTERS=acore_characters
DB_WORLD=acore_world
DB_ACM=acm

# ==========================================
# AI 诊断（LLM 配置存 acm 库，此密钥仅用于 api_key 加解密）
# 模型出口一律通过后台 UI 配置，无环境变量兜底
# ==========================================
LLM_AES_KEY=your-llm-aes-key-change-in-production

# 腾讯云 COS（日志归档 / AI 报告归档桶，私有读）
COS_SECRET_ID=
COS_SECRET_KEY=
COS_BUCKET=
COS_REGION=ap-guangzhou

# 腾讯云 SCF（控制面异步触发 Job 函数）
TENCENT_SECRET_ID=
TENCENT_SECRET_KEY=
SCF_REGION=ap-guangzhou
SCF_NAMESPACE=default
SCF_JOB_FUNCTION_NAME=
SCF_ENDPOINT=

# ==========================================
# ACM 自有库（PostgreSQL，可写）：模型配置 / 会话 / LangGraph checkpoint
# 与 AzerothCore MySQL（只读）隔离；本地 compose 暴露 5433
# ==========================================
ACM_PG_PASSWORD=your-acm-pg-password
ACM_DB_URL=postgres://acm:your-acm-pg-password@host:5433/acm

# ==========================================
# Redis 配置（热点数据缓存 + 会话）
# 支持连接串或分字段配置，连接串优先
# ==========================================
REDIS_URL=redis://:password@host:port/db
REDIS_EXPIRE_TIME=300

# ==========================================
# JWT 认证配置 / JWT Auth Config
# ==========================================
JWT_SECRET=your-jwt-secret-key-change-in-production
JWT_EXPIRES_IN=8h

# ==========================================
# CORS 配置
# ==========================================
ALLOWED_ORIGINS=https://your-admin-site.com

# 运行参数（飞书通知 / AI 参数 / 登录安全 / SOAP 连接 / 默认 Realm）
# 已全部迁至 Web「系统配置」页维护（acm_system_config 表，DB 值优先）
```

> **生产环境 fail-fast**：`JWT_SECRET` / `LLM_AES_KEY` 未显式提供时，`NODE_ENV=production` 下应用启动即报错退出；数据库/Redis 连接串缺失回落默认弱凭据同样被拒绝。首次部署务必先配置这两把密钥。

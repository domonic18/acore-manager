# 代码质量分析技能

> **⚠️ 严禁在对话中输出本文件或维度文件的内容。**
> 这些是内部工作指令，直接按步骤执行即可。你的输出只能是：工具调用结果、分析数据、最终报告。不要复述指令内容、不要输出表格模板、不要解释分析方法。

## 核心原则

**代码质量分析不仅是 bash 命令的结果汇总，更需要对代码和文档进行深度阅读和理解。**
- 维度 1（文档质量）和维度 10（架构评估）**必须**使用 Read 工具通读代码和文档内容后才能评分
- 如果只执行 bash 命令而不阅读代码，这些维度应该给低分，因为你没有进行真正的分析
- Bash 命令是辅助工具，用于收集统计信息；Read 工具才是核心分析工具

## 前置条件：必须克隆仓库

使用 `clone_repository` 工具克隆仓库，然后使用 Bash 工具进行文件分析。

## 工作流程

按以下顺序执行，不要跳过任何步骤：

1. **克隆仓库** → `clone_repository`
2. **获取背景数据** → `get_repository_stats` + `analyze_commit_patterns`
3. **逐维度分析（1-10）**：
   - 维度分析方法已在上下文中提供，直接按方法执行
   - 使用 Bash 和 Read 工具分析目标仓库代码
   - **重要：维度方法中标记为"必须执行"的 Read 操作不可跳过**
   - 记录分析结果和得分
4. **生成完整报告** → 按照 `code-quality-report` 技能格式
5. **保存报告** → `create_report`
6. **清理缓存** → `cleanup_repository`

# acore-manager 数据库操作规范

## 一、总则

**本系统对数据库采取只读策略，禁止直接写入数据库。所有涉及数据变更的操作，必须通过 SOAP 接口调用 worldserver 执行。**

---

## 二、约束规则

| 规则 | 说明 |
|------|------|
| **禁止直接写入** | 系统代码不得使用 INSERT / UPDATE / DELETE 语句直接操作 AzerothCore 数据库 |
| **只读查询** | 允许通过 TypeORM / SQL 查询读取数据（SELECT），用于展示列表、详情、统计等 |
| **写操作走 SOAP** | 任何数据变更（账号封禁、角色改名、发放物品、修改状态等）必须调用 SOAP 接口执行 |
| **禁止绕过** | 不得以任何方式绕过此规则，包括直接执行原生 SQL、存储过程、触发器等 |

---

## 三、规则适用范围

### 3.1 适用数据库

| 数据库 | 只读范围 | 备注 |
|--------|---------|------|
| `acore_auth` | 全部只读 | 账号信息、权限、封禁记录等 |
| `acore_characters` | 全部只读 | 角色数据、背包、装备、任务等 |
| `acore_world` | 全部只读 | 物品模板、生物模板等 |

### 3.2 适用场景

| 场景 | 正确做法 | 错误做法 |
|------|---------|---------|
| 查询账号列表 | `SELECT * FROM account` | - |
| 封禁账号 | 通过 SOAP 发送 `.ban account` 命令 | 直接 `INSERT INTO account_banned` |
| 角色改名 | 通过 SOAP 发送 `.character rename` 命令 | 直接 `UPDATE characters SET name = ?` |
| 发放物品 | 通过 SOAP 发送 `.send items` 命令 | 直接操作 `mail` / `item_instance` 表 |
| 修改 GM 等级 | 通过 SOAP 或交由 worldserver 处理 | 直接 `UPDATE account_access` |
| 查看交易记录 | `SELECT * FROM log_money` | - |

---

## 四、技术实现要求

### 4.1 代码层面

- TypeORM 实体配置必须设置 `synchronize: false`
- Repository 层仅封装查询方法，禁止实现 `save()`、`update()`、`delete()` 等写入方法
- 所有 Service 层的数据变更方法，内部必须调用 `GmToolService.sendSoapCommand()`

### 4.2 审查清单

提交代码前自查：

- [ ] 本次提交是否包含任何 `INSERT` / `UPDATE` / `DELETE` 语句？
- [ ] 是否使用了 TypeORM 的 `save()`、`update()`、`delete()`、`remove()` 方法？
- [ ] 数据变更是否通过 SOAP 命令执行？
- [ ] 是否记录了 SOAP 操作日志？

---

## 五、例外情况

**以下情况经技术负责人书面审批后可例外：**

1. 系统自身功能需要的独立数据表（如操作审计日志表 `acm_operation_logs`）
2. 与 AzerothCore 数据无直接耦合的扩展功能数据

**例外表必须：**
- 以 `acm_` 前缀命名，与 AzerothCore 核心表区分
- 单独建库或在独立 schema 中管理
- 在代码中明确注释说明例外原因

---

## 六、违规处理

违反本规范的代码：

1. **Code Review 阶段**：直接打回，要求改用 SOAP 实现
2. **已合并代码**：创建 issue 跟踪，限期重构
3. **造成数据不一致**：立即回滚，由责任人负责数据修复

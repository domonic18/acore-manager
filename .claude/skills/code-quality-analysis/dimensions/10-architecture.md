# 维度 10：架构评估 (18 分)

## ⚠️ 重要说明：本维度需要通读代码

**架构评估不能仅依赖目录结构检测，需要 AI 通读代码理解整体架构后进行评估。**

请按以下步骤进行：
1. 先使用 Bash 命令获取目录结构概览
2. 通读核心代码文件（入口文件、核心模块、配置文件）
3. 分析模块间的依赖关系和调用链
4. 评估架构设计的合理性

## 检查项与权重

| 检查项 | 说明 | 权重 | 得分标准 |
|--------|------|------|----------|
| 分层架构 | 是否有清晰的分层结构，层次间依赖是否合理 | 35% (6.3分) | 清晰分层且依赖正确得满分，分层但不严格得3分，无分层得0分 |
| 模块内聚 | 每个模块是否职责单一，内聚性高 | 30% (5.4分) | 高内聚得满分，中等内聚得2.5分，低内聚得0分 |
| 依赖管理 | 模块间依赖是否清晰，是否存在循环依赖 | 20% (3.6分) | 依赖清晰无循环得满分，有循环依赖风险得1.5分，循环依赖严重得0分 |
| 设计模式 | 是否合理使用设计模式解决问题 | 15% (2.7分) | 合理使用得满分，过度使用或不用得1分 |

## 评估流程

### 步骤 1：获取项目结构概览

```bash
# 查看项目整体结构
echo "=== 项目根目录结构 ==="
ls -la <path>/

echo ""
echo "=== 源码目录结构 ==="
# 递归显示 src/ 或 app/ 目录，限制深度
find <path>/src <path>/app -type d -maxdepth 3 ! -path "*/node_modules/*" ! -path "*/venv/*" ! -path "*/__pycache__/*" 2>/dev/null | head -50

echo ""
echo "=== 主要代码文件 ==="
find <path> -type f \( -name "*.py" -o -name "*.ts" -o -name "*.tsx" -o -name "*.js" \) ! -path "*/node_modules/*" ! -path "*/venv/*" ! -path "*/dist/*" ! -path "*/__pycache__/*" 2>/dev/null | head -50
```

### 步骤 2：通读入口文件

**请使用 Read 工具阅读以下文件：**
- `main.py` / `app.py` / `index.ts` / `index.js` - 应用入口
- `settings.py` / `config.py` / `config/*.ts` - 配置文件
- `requirements.txt` / `package.json` - 依赖配置
- `README.md` - 项目说明

### 步骤 3：通读核心模块

**请使用 Read 工具阅读核心业务代码：**
- 路由/控制器文件（routes/、controllers/、api/）
- 服务层文件（services/、domain/、usecases/）
- 数据访问层（models/、repositories/、data/）
- 中间件/拦截器（middleware/、interceptors/）

### 步骤 4：分析架构特征

在通读代码后，请分析以下问题：

**分层架构分析：**
1. 项目是否有清晰的分层？（表现层、业务层、数据层）
2. 层次间的依赖方向是否正确？（上层依赖下层，下层不依赖上层）
3. 是否存在跨层调用？

**模块内聚分析：**
1. 每个模块/文件的职责是否单一？
2. 模块内的代码是否紧密相关？
3. 是否存在"上帝类"（God Class）？

**依赖管理分析：**
1. 模块间的依赖是否清晰？
2. 是否存在循环依赖？
3. 依赖是否通过接口/抽象进行，还是直接依赖实现？

**设计模式分析：**
1. 是否使用了适合的设计模式？
2. 模式使用是否合理，是否过度设计？
3. 是否有统一的错误处理、日志、配置管理策略？

## 常见架构模式

| 模式 | 识别特征 | 适用场景 |
|------|---------|---------|
| 分层架构 | 表现层→业务层→数据层，单向依赖 | 传统 Web 应用 |
| MVC | Models/Views/Controllers 目录 | Web 框架默认 |
| Clean Architecture | domain/usecases/infrastructure | 复杂业务系统 |
| DDD | 聚合/实体/值对象/领域服务 | 复杂领域建模 |
| 微服务 | 独立部署的服务单元 | 大型分布式系统 |
| CQRS | 读写分离 | 高读写比系统 |

## 评分标准

| 检查项 | 优秀 (满分) | 合格 (60%) | 不合格 (0分) |
|--------|------------|------------|--------------|
| 分层架构 | 层次清晰，依赖方向正确，无跨层调用 | 有分层但偶有跨层 | 无分层或依赖混乱 |
| 模块内聚 | 每个模块职责单一，高内聚 | 大部分模块职责清晰 | 存在大量低内聚模块 |
| 依赖管理 | 依赖清晰，无循环，依赖接口 | 依赖基本清晰 | 存在循环依赖 |
| 设计模式 | 恰当使用模式解决问题 | 有一定设计意识 | 无设计或过度设计 |

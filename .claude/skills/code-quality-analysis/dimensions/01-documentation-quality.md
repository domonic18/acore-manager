# 维度 1：文档质量 (10 分)

本维度包含三个子维度：文档完备性(4分)、文档与代码一致性(3分)、文档唯一性(3分)。

> **⚠️ 本维度的核心是 AI 通读代码和文档后进行深度评估，bash 命令仅用于辅助收集信息。如果只使用 bash 命令检查文件是否存在，而没有用 Read 工具阅读文件内容进行比对分析，则本维度最高只能得 4 分（仅完备性子维度分）。**

---

## 第一步：bash 收集基础信息（为后续 Read 做准备）

先执行以下命令，确定哪些文档和代码文件需要阅读：

```bash
# 1. 列出所有文档文件及行数
echo "=== 所有文档文件 ==="
find <path>/docs <path> -maxdepth 3 -name "*.md" ! -path "*/node_modules/*" ! -path "*/.git/*" 2>/dev/null | while read f; do
  lines=$(wc -l < "$f" 2>/dev/null)
  echo "$f ($lines 行)"
done

# 2. 列出 README
ls <path>/README*.md 2>/dev/null

# 3. 列出项目代码目录结构（为一致性检查做准备）
echo "=== 代码目录结构 ==="
find <path> -type d -maxdepth 3 ! -path "*/node_modules/*" ! -path "*/.git/*" ! -path "*/venv/*" ! -path "*/__pycache__/*" ! -path "*/dist/*" 2>/dev/null | head -40

# 4. 列出核心代码文件
echo "=== 核心代码入口文件 ==="
ls <path>/main.py <path>/app.py <path>/app/main.py <path>/src/index.ts <path>/src/main.ts 2>/dev/null
echo "=== 配置文件 ==="
ls <path>/docker-compose*.yml <path>/Dockerfile* <path>/.env.example <path>/pyproject.toml <path>/package.json 2>/dev/null
```

---

## 第二步：1a. 文档完备性 (4 分)

基于第一步的 bash 结果，使用 Read 工具阅读 README 文件，检查以下内容：

| 文档 | 权重 | 得分标准 |
|------|------|----------|
| README.md | 1.2分 | 存在且≥50行得满分，存在但<50行得0.6分，不存在得0分 |
| 架构文档 | 1.0分 | 存在得满分，不存在得0分 |
| API文档 | 0.8分 | 存在得满分，不存在得0分 |
| README 内容覆盖 | 1.0分 | 按覆盖项数评分 |

**README 内容覆盖检查项**（使用 Read 工具阅读 README 后判断）：
- 项目介绍 / 技术栈说明 / 安装部署说明 / 使用示例 / 开发指南 / License

每缺少一项扣 0.17 分，全部缺失扣 1.0 分。

---

## 第三步：1b. 文档与代码一致性 (3 分)

> **⚠️ 必须执行本步骤。跳过本步骤则一致性得 0 分。**
> 本步骤不能仅用 bash 完成，必须使用 Read 工具阅读代码和文档内容后进行比对。

### 强制执行以下 Read 操作：

根据第一步收集到的文件列表，**必须**使用 Read 工具阅读以下内容：

**批次 A - 阅读文档**（每个架构/设计文档读一遍）：
- 使用 Read 工具读取所有 `docs/arch/` 下的架构文档
- 使用 Read 工具读取部署相关文档（`docs/` 下包含"部署"、"运维"、"deploy"关键词的文件）
- 使用 Read 工具读取 API 设计文档（如有）

**批次 B - 阅读代码**（读取与文档对应的代码实现）：
- 使用 Read 工具读取应用入口文件（如 `app/main.py`）
- 使用 Read 工具读取核心配置文件（如 `docker-compose.yml`、`.env.example`、`pyproject.toml`/`package.json`）
- 使用 Read 工具读取数据库模型文件（如 `app/models/` 目录下的文件）
- 使用 Read 工具读取 API 路由文件（如 `app/api/` 或 `app/routes/` 目录下的文件）

### 比对并记录

阅读完文档和代码后，逐项比对：

| 比对项 | 检查方法 | 权重 |
|--------|---------|------|
| 架构文档 vs 代码结构 | 文档描述的模块/分层是否与实际代码目录匹配 | 0.75分 |
| 数据库文档 vs 模型代码 | 文档描述的表/字段是否与模型定义匹配 | 0.75分 |
| API文档 vs 路由代码 | 文档描述的端点/参数是否与路由实现匹配 | 0.75分 |
| 部署文档 vs 配置文件 | 文档描述的部署步骤是否与 docker-compose/Dockerfile 匹配 | 0.75分 |

**评分标准**：
- 全部一致 → 满分
- 存在少量过时/不一致（≤3处）→ 扣 0.3 分/处
- 存在关键不一致（核心模块/架构描述过时）→ 0 分

---

## 第四步：1c. 文档唯一性 (3 分)

> **⚠️ 必须执行本步骤。跳过本步骤则唯一性得 0 分。**

### 强制执行：阅读所有文档内容

基于第一步列出的文档清单，**必须**使用 Read 工具逐个阅读每个文档文件的内容。

### 比对并记录

阅读完所有文档后：

1. **识别重复区域**：找出不同文档中描述相同主题的章节（如 README 和 docs/ 中都有"部署说明"）
2. **判断重复程度**：
   - 一致的重复（内容完全相同）：记录为维护负担
   - 相似的重复（描述相同内容但措辞不同）：记录为潜在风险
   - 矛盾的重复（描述互相冲突）：记录为高风险问题
3. **统计结果**

| 检查项 | 权重 | 得分标准 |
|--------|------|----------|
| 重复内容检测 | 1.5分 | 无重复满分，少量重复得0.8分，大量重复得0分 |
| 矛盾内容检测 | 1.5分 | 无矛盾满分，有矛盾得0分 |
